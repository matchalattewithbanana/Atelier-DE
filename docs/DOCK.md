# Native dock refinement

The dock uses a stable task tile for each native window, keyed by compositor session token and window ID. Changing the title, focus, workspace or inventory order no longer destroys all window controls. Only removed identities are removed, only new identities are constructed, and surviving children move only when their order changes. Titles and accessible descriptions update in place. A restarted compositor produces new session-bound identities, even if numeric IDs repeat. Activation continues through the existing validated native task backend; a request is not treated as proof of focus.

Pinned applications retain their exact case-sensitive desktop-entry matching and focus/cycle behavior. Every native window still has an individual task tile, including unmatched windows; pinned windows are not yet collapsed into a grouped context menu. Both pin and task tiles use an understated running mark and wider focused pill, with a count for multiple pinned windows. A truncated inventory shows a known lower-bound count (or question mark when no matching windows are visible); an unavailable native inventory shows unknown rather than claiming no windows. External compositors retain launch-only pins. Count space is reserved to avoid changing the tile's width when the count appears. Existing pin launch fallback is unchanged.

The focused pill takes inspiration from [Caelestia's ActiveIndicator](https://github.com/caelestia-dots/shell/blob/main/modules/bar/components/workspaces/ActiveIndicator.qml), which separately animates the edges of its workspace highlight. This is an original GTK dock adaptation, not its moving workspace mask. The dock uses scoped CSS current-color marks with 6px/22px widths and an existing local motion duration for the width transition; reduced motion requests zero duration. The user's configured button radius, icon size, transparency, colors, auto-hide, and fullscreen policy remain unchanged. The existing width cap of 640 logical pixels is reduced to fit the panel surface's monitor on map, with scroll overflow. No actual cross-output live resizing, hover enlargement, spring motion, context-menu actions or external compositor task enumeration is introduced. Native GTK geometry, styling and multi-monitor behavior require real desktop testing.

Tests cover exact pin matching, incomplete inventory, stable task identity across metadata changes, session restart invalidation, and scoped reduced-motion CSS. The existing half-second bounded local task snapshot check remains; this patch reduces widget churn rather than replacing that polling mechanism. No additional dependencies or saved configuration fields.
