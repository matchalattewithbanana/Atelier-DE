# Native dock refinement

The dock uses a stable task tile for each native window, keyed by compositor session token and window ID. Changing the title, focus, workspace or inventory order no longer destroys all window controls. Only removed identities are removed, only new identities are constructed, and surviving children move only when their order changes. Titles and accessible descriptions update in place. A restarted compositor produces new session-bound identities, even if numeric IDs repeat. Activation continues through the existing validated native task backend; a request is not treated as proof of focus.

Pinned applications retain their exact case-sensitive desktop-entry matching and focus/cycle behavior. On native layer-shell v4+ sessions, a window with exactly one matching installed pin is grouped behind that pin's contextual menu. Unmatched and ambiguous windows retain individual tiles. Older protocol versions retain all individual tiles. Both pin and task tiles use an understated running mark and wider focused pill, with a count for multiple pinned windows. A truncated inventory shows a known lower-bound count (or question mark when no matching windows are visible); an unavailable native inventory shows unknown rather than claiming no windows. External compositors retain launch-only pins. Count space is reserved to avoid changing the tile's width when the count appears. Existing pin launch fallback is unchanged.

The focused pill takes inspiration from [Caelestia's ActiveIndicator](https://github.com/caelestia-dots/shell/blob/main/modules/bar/components/workspaces/ActiveIndicator.qml), which separately animates the edges of its workspace highlight. This is an original GTK dock adaptation, not its moving workspace mask. The dock uses scoped CSS current-color marks with 6px/22px widths and an existing local motion duration for the width transition; reduced motion requests zero duration. The user's configured button radius, icon size, transparency, colors, auto-hide, and fullscreen policy remain unchanged. The existing width cap of 640 logical pixels is reduced to fit the panel surface's monitor on map, with scroll overflow. No actual cross-output live resizing, hover enlargement, spring motion, window close/minimize actions or external compositor task enumeration is introduced. Native GTK geometry, styling and multi-monitor behavior require real desktop testing.

Tests cover exact pin matching, incomplete inventory, stable task identity across metadata changes, session restart invalidation, and scoped reduced-motion CSS. The existing half-second bounded local task snapshot check remains; this patch reduces widget churn rather than replacing that polling mechanism. No additional dependencies or saved configuration fields.

## Contextual window groups

Native pins have a primary launch/focus/cycle action and a secondary window menu. The menu is an ordinary GTK popover anchored to the trailing button, not a new layer surface. The 2px split gap and 4px inner radius adapt Material 3 Expressive split-button tokens; outer corners retain the user's configured radius. This is a desktop adaptation, not a complete Material split-button implementation. Menu contents are read afresh on show from the validated local task inventory and include individual titles, workspaces, focused state, and an explicit Launch application action (the application decides whether to open a new instance). Window actions use the reviewed session and window identity and the backend revalidates against a fresh inventory before sending activation. Failed requests are reported in the menu. A menu is a reviewed snapshot, not a continuously changing list; reopen to refresh. Partial and unavailable inventory are identified explicitly. Uninstalled pins cannot hide tasks, and ambiguous matches are never collapsed. External compositor support remains launch-only; protocol versions below 4 keep the previous individual native task list.

The dock requests on-demand keyboard focus only while contextual menus are mapped, restores None when the last closes, and suppresses ordinary auto-hide while a menu is open. Fullscreen hiding still overrides this behavior. No window termination, minimize, pin editing or privileged actions are introduced. Tests cover exact, missing and ambiguous grouping matches; GTK menu positioning, focus, auto-hide, keyboard interaction and real compositor behavior still require desktop acceptance. No additional dependencies or saved configuration changes.
