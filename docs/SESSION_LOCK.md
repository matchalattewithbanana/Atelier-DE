# Native session lock security contract

Status: internal foundation only. No advertised ext-session-lock global, no lock command, and no runtime activation flag. Do not treat Atelier as a secure locker.

## Current implementation

- Exact lock-object identity and monotonic presentation generations; only the current confirmed owner can unlock. A duplicate request or stale frame completion cannot alter the current lock. Losing the owner leaves an orphaned protected state.
- A native protected-frame token is captured from the rendered state, recorded only after successful atomic submission and consumed at page-flip completion. A previous desktop flip cannot acknowledge a lock. Full opaque-black repaint; no ordinary scene, cursor surface, frame callback, ordinary input or workspace activation. Nested never claims host protection.
- These internal transitions are intentionally unreachable until a complete protocol adapter exists.

## Required before exposing the protocol

Smithay v0.7.0's session-lock `lock.rs` dispatch posts InvalidUnlock for a nonlocked request but still calls `state.unlock()` and clears its output bookkeeping. A bare implementation of its handler is insufficient. Inspect the pinned upstream source and enforce exact resource authorization before forwarding GetLockSurface and UnlockAndDestroy. A same-client second object must not unlock or poison the current owner's output registry. Reject invalid requests without changing the accepted owner's state. Bind lifetime to the actual resource; never acknowledge until a protected frame has completed for all active outputs.

Implement and test the following before enabling any global:
1. Dispatch isolation for rejected/duplicate/foreign lock objects; configure only accepted owner surfaces for actual outputs. Handle surface destruction and disconnect without falling back to the desktop.
2. Lock-only scene over opaque black, output-local clipping, no ordinary cursor or decorations. All pending scanout slots are invalidated; no old desktop data can reappear. Input is routed only to accepted lock surfaces with correct focus, keyboard state, pointer coordinates and protocol roles. Cancel or safely replace ordinary grabs and deny ordinary selection/clipboard and drag access at lock entry; restore only after authorized unlock. No ordinary input delivered while protected.
3. Handle compositor/seat/route loss, suspend and output changes without revealing previously protected desktop content. The current experimental KMS backend exits on route or seat loss and restores scanout; this is a release blocker for secure locking, not a supported recovery path.
4. Real malicious-client tests: rejected second lock, same-client second resource, invalid unlock, disconnected owner before and after acknowledgment, destroy/recreate surface, stale flips, input focus theft, alpha holes, output loss, suspend, VT switches, compositor crash. Verify actual screen and input on spare TTY hardware. Provide controlled recovery without weakening authentication.
5. Only then advertise the protocol on the verified native backend. Keep nested separate and do not advertise host security. Configure trusted lockers independently and test authentication with the installed PAM configuration.

No production security claim follows from unit tests or protocol availability.

## Guarded protocol adapter (still disabled)

The native build now implements Smithay's lock-manager and resource dispatch traits without creating the global. A custom lock-object dispatcher checks exact resource ownership and confirmed presentation before forwarding unlock, rejects foreign/duplicate-output surface construction before upstream bookkeeping, and handles owner destruction by retaining the protected state. The lock callback stores Smithay's confirmation until the native protected flip completes. The protected scene can draw only the accepted mapped lock-surface tree over opaque black; no normal surface or ordinary cursor is drawn. Only lock-tree frame callbacks are eligible in protected states. No input is routed to the lock surface yet.

The pinned Smithay lock-surface resource data is private and does not expose exact resource-to-root lifetime tracking; this adapter conservatively clears the accepted tree on same-client lock-role destruction and refuses a replacement for the same lock. That can blank the lock UI, but cannot reveal the desktop. Precise role lifetime/replacement, root commit/size validation, real malicious-client dispatch tests, focus and grab isolation, selection isolation, and seat/route-loss recovery are required before registration. The original KMS backend still restores the original scanout on exit. Do not advertise or enable the protocol yet.

## Lock input routing groundwork

Native input is now separated by focus ownership. On admission, active keyboard/pointer grabs cause refusal rather than inheriting an ordinary drag. Focus and data-device focus are cleared at the protection boundary; the previous clipboard selection is cleared (deliberate loss, not preserved across lock). A physical key/button release gate tracks inputs independently of focus and delays new focus until all held controls are released. The event which clears the gate is processed with no focus. The accepted mapped root must match the actual logical buffer size as well as configure state; keyboard goes only to that root and pointer hit-testing is restricted to its tree. No desktop shortcuts, task/workspace commands, client cursor images or new data-device drag/selection requests are admitted while protected. A compositor-owned cursor glyph may be drawn when the lock root is mapped. Unlock clears locker focus and restores a surviving desktop window only after the release gate. Surface loss clears focus and does not unlock. No protocol global is created.

This is not a complete clipboard security boundary: outstanding previously issued data offers, multi-device pressed-state accounting, stale same-client role lifetime, lock-client DnD/resource requests, recovery/seat loss and adversarial integration tests still need review. Do not advertise secure locking until these are resolved and actual hardware acceptance passes.

## Exact lock resource lifetime

The native adapter now owns ext-session-lock manager, lock and surface dispatch using Smithay's public compositor primitives, instead of forwarding to the pinned private session-lock bookkeeping. Each accepted surface stores the actual role resource and root, configure serial, expected logical dimensions and committed state. Only exact role or root destruction clears it; the same accepted owner can create a fresh role on a new root after destruction. Stale role destruction and acknowledgments cannot affect a replacement. Rejected lock resources cannot create surfaces or unlock. Root commits are checked after buffer processing and before use, and invalid serials, missing buffers and wrong dimensions are rejected and blank the protected scene. A new root must acknowledge its configure and commit the correct buffer before receiving input or rendering. The compositor explicitly refuses restoring the original framebuffer on protected-session exit, but descriptor release, VT, GPU, suspend and seat-manager behavior remain unverified; this does NOT provide a secure recovery guarantee. Prior descriptions of conservative same-client role destruction and Smithay delegation are superseded by this section. No global is registered. Real protocol-client integration tests and hardware recovery are still required. The adapter currently supports a single fixed unscaled output, no output reconfiguration, and no orphaned-owner re-lock recovery.

## Protocol wire regression tests

The native-session unit-test build registers the lock global only inside an in-process private Wayland display connected by Unix socket pairs. Raw version-1 protocol requests exercise the production dispatch implementation, not a simulated lock handler. Tests cover the locked event after a synthetic protected-frame completion, valid unlock, rejected same-client unlock, foreign rejected surface construction, exact role replacement and stale root destruction, invalid configure serial, commit before acknowledgment, premature unlock and owner disconnect before/after confirmation. The tests do not use DRM, actual presentation, PAM, live input devices or a desktop socket. The ordinary native and nested backends still do not advertise the global. Real buffer attachment, input events, data offers and actual recovery remain to be tested.

## Actual shared-memory buffer tests

Private wire tests now create wl_shm pools using real file descriptors passed through SCM_RIGHTS, attach ARGB8888 buffers, and verify that a configured output-sized lock root maps and receives only its own keyboard/pointer focus. Invalid dimensions, null-buffer commits, preexisting attached buffers and role replacement are checked against actual Smithay buffer processing. The tests still simulate protected-frame completion rather than drive a GPU or physical seat. No production global is exposed.

## Physical input aggregation

The shared input router tracks control holders per backend device ID and forwards only the first press and final release of a logical key/button. Repeated same-device presses and unknown releases do not change the seat state. Device removal synthesizes only final releases for controls no other device holds. The release quarantine is sampled before applying the transition; the final release is dispatched in the previous focus domain before restoring focus. Tests cover two keyboards/pointers holding the same codes, duplicate/unknown events, device removal and ID reuse. This addresses the ordinary multi-device accounting limitation, not suspend/resume or unreported device loss. Backend device IDs must be unique while connected; nested Winit is a single virtual device. No hardware validation or global registration is introduced.

## Seat continuity and protected display coverage

The libseat notifier now latches every PauseSession event. ActivateSession cannot erase a pause, even when both occur in a single event-loop dispatch. The native backend checks this continuity before input forwarding, processing flips, submitting frames, and restoring or explicitly destroying framebuffer state. On interruption it stops using the old route; no stale flip can confirm a lock and no explicit original-FB restoration or cleanup is attempted after reactivation. Before protected submissions and flip acknowledgments, revalidate the exact connector/CRTC/mode/primary plane and expected framebuffer; refuse other active CRTCs or bound planes, including hardware overlays/cursors. This intentionally conservative single-output restriction does not implement multi-monitor lock coverage or guarantee secure scanout on VT/seat release. The current backend still exits on interruption. Actual recovery requires retaining the compositor and rebuilding the seat/DRM/GBM route, presenting a verified black frame before resuming input or client dispatch, and testing the kernel/seat-manager transition on hardware. No session-lock global is registered outside tests.

## Protected recovery quarantine

A protected session which exits its normal render loop removes the libinput source and stops Wayland client dispatch entirely. Unless explicitly terminating, it continues servicing only the seat notifier. For each newly active seat epoch (at most eight attempts per session), it checks that the original single-output route is still exact, that the current framebuffer belongs to Atelier, and that no other active CRTC or bound plane exists. It allocates a fresh CPU-zeroed XRGB8888 dumb buffer, tests the replacement, performs a blocking atomic commit and verifies the resulting framebuffer. No old GBM slot, renderer fence, damage history or page-flip event is reused. Recovery never acknowledges a lock or resumes clients/input, never restores the old framebuffer, and never writes a changed or external route. Failure leaves the session quarantined with a logged error. Kernel allocations are bounded and retained until descriptor release to avoid removing a potentially active framebuffer. Ctrl+C/termination exits quarantine; actual descriptor release remains unverified. This is an emergency best-effort black presentation, not secure automatic resume: inactive VT visibility, prior framebuffer exposure before reactivation, driver support for dumb buffers, old pending flips, mode changes and multi-output coverage are not guaranteed. Normal sessions still do not register the protocol. Physical testing and a full fresh renderer/input recovery path are release blockers.

## Fresh graphics generation after protected failure

Startup and protected reconstruction now share an initializer for a new GBM device/EGL context and scanout slots. Every slot is fully cleared to opaque black and its fence completed before registering its framebuffer. After emergency CPU black is verified, quarantine creates a fresh renderer and two initialized slots, tests each, commits a new black slot and checks exact route/FB ownership. Reconstructed generations and their framebuffer IDs are retained until descriptor release, including partial/ambiguous attempts; CPU recovery IDs are tracked before test/commit as well. The eight-epoch limit bounds allocation attempts. Quarantine periodically revalidates the last verified black scanout and drops that claim if topology, framebuffer or seat epoch changes. It never overwrites a foreign route or resumes ordinary client dispatch, and does not retry in the same epoch. This reconstructs graphics on the existing seat descriptor only; it is not a complete DRM device reopen, input reset, authenticated recovery or multi-output resume. No runtime global is registered. Hardware allocation, fence and VT behavior remain untested.

## Recovery authority and logical input reset

Entering protected quarantine now revokes the previous lock object, clears focus/grabs and clipboard, and drains aggregated logical keys/buttons into an unfocused seat. This resets stale logical state but is not a physical input-device neutrality attestation. A compositor-private socket pair can grant one exact Wayland client the right to claim an orphaned lock. No public request, PID, UID, ordinary connection or filesystem endpoint grants recovery. The old owner cannot unlock; a replacement starts in a fresh pending generation and requires a new protected presentation before input focus or unlocking. The wire harness exercises private admission, public rejection, stale presentation/owner rejection and mapped focus after new confirmation. The private endpoint has no production caller; a trusted launcher, PAM-backed locker, fresh libinput source, hardware verification and safe request-dispatch handoff remain necessary. The current quarantine does not dispatch Wayland clients or resume input. A disconnected unclaimed grant requires another explicit internal reset; no ordinary fallback is allowed.

## Private recovery process supervision

The internal supervisor reserves the fixed administrator-installed executable /usr/lib/atelier/atelier-recovery-locker and PAM service /etc/pam.d/atelier-recovery-locker. Both must be regular root-owned files beneath protected non-symlink directories; no user-selectable command, config, shell or inherited environment is accepted. The private connection is passed as WAYLAND_SOCKET=0 with stdin containing the socket; stdout/stderr are discarded. A retained duplicate can shut down even fork-inherited socket copies. The supervisor polls the actual child and exact compositor confirmation, not its exit status or a readiness notification. Failure/timeout/explicit stop revokes only the matching grant or owner before closing the socket and reaping the child. A ten-second pending admission limit applies before confirmed presentation, not to subsequent authentication. Tests cover scoped cancellation, stale grants, protected file checks and process/socket cleanup. The dedicated executable and PAM service are not yet implemented or installed; the supervisor is not wired into quarantine and must not be advertised as working authentication. Swaylock's upstream SIGUSR1 unlock path means it is not chosen as this recovery authority without stronger isolation. Same-UID process interference, PAM configuration and the actual recovery handoff still require review and physical acceptance.

The accepted recovery owner now retains the exact private client identity independently of live protocol-resource lookup. The supervisor distinguishes a pending grant or pending presentation from a confirmed owner and stops promptly on its next poll when neither state remains (including completion or revocation). Scoped cleanup cannot cancel a subsequent grant. An unclaimed disconnected socket without a detectable child exit is still bounded by the admission timeout. Wire tests cover pending, confirmed, revoked, unlocked and disconnected states; production handoff remains disabled.

## Recovery authentication primitive (not wired)

The independent atelier-recovery-auth crate has an opt-in Linux-only pam feature. Its fixed service is atelier-recovery-locker and its account is resolved from the real non-root UID (real and effective UID must match), never a caller-provided username. Missing or untrusted dedicated service files fail closed rather than knowingly relying on PAM's other fallback. It checks both pam_authenticate and pam_acct_mgmt with null tokens disallowed, verifies PAM_USER after each successful phase, requires one hidden password prompt, and rejects username prompts, repeated challenges and unexpected conversation styles. Password buffers supplied by the caller are cleared on return; PAM owns its allocated copies and their lifetime. No message, password or PAM error detail is logged by this library. A password-only policy is intentional for the initial implementation; MFA and expired-password workflows are not supported. The system policy and its modules remain administrator-controlled and must be reviewed independently. The metadata check is not a complete policy or TOCTOU attestation.

CI links against system Linux-PAM and exercises the conversation callback with synthetic data, without reading real credentials or installing a PAM service. The crate has no executable or protocol connection, does not install configuration, and its decision is not yet an unlock capability. Process isolation (including same-UID interference), secure UI and input, actual PAM service tests, and native recovery handoff remain release blockers. Do not enable the session-lock global.

## One-shot authentication worker (not wired)

The optional atelier-recovery-auth-worker executable has no Wayland connection or unlock authority. It disables dumpability and sets both core-dump limits to zero before reading an inherited connected AF_UNIX stream on fd 0. It checks the real/effective non-root UID and peer UID, marks the descriptor close-on-exec, sets per-operation I/O timeouts, and accepts one versioned bounded password frame terminated by a write-half shutdown. Trailing bytes, repeated requests, invalid lengths, truncated messages and embedded NULs are rejected before invoking PAM. The buffer is cleared on all exits. A two-byte response is a transport-level authentication decision, not an unlock token; exit status alone conveys no authentication result. Synthetic tests cover both decisions, malformed frames, actual socket half-close, and process hardening in a disposable child.

This is process hardening, not complete same-UID isolation. A future trusted parent must create the socketpair, execute the fixed administrator-installed worker with a sanitized environment, close unrelated descriptors, enforce an overall deadline including PAM, and verify the exact child and connection before consuming the decision. The peer UID is not a proof of parent identity; pre-main/exec-time exposure, a compromised parent, PAM modules and same-user signal denial of service remain outside these protections. No no_new_privs or blanket syscall filter is imposed yet because the installed PAM stack may require privileged helpers; its actual requirements must be tested before applying restrictions. No binary is installed, no PAM policy is provisioned, and neither the locker nor compositor launches the worker. Native locking remains disabled.

## Trusted worker launcher (not wired)

The library now provides a fixed-path launcher for /usr/lib/atelier/atelier-recovery-auth-worker. The future locker must harden its process before accepting secrets (non-root matching real/effective UID, non-dumpable, zero core limits); the launcher verifies those conditions again before spawning. It refuses writable or non-root-owned executables and directories, symlinks and set-ID executable mode bits. The worker receives a fresh private socket on fd 0, a sanitized environment and no other deliberately inherited descriptors. A Linux close_range CLOEXEC operation rejects unsupported kernels instead of silently leaking non-stdio descriptors. The parent's mutable password is erased after transmission or on any error. A single monotonic 30-second deadline spans socket I/O and child-exit observation. The reply must contain exactly the expected version and decision bytes followed by EOF, and the exact child must exit successfully before the deadline. Errors, malformed responses and failed children never authorize unlocking. Cleanup shuts down by closing the channel and terminates/reaps the direct child; process spawn and kernel-blocked reaping cannot be given a hard wall-clock guarantee. Descendant PAM helper lifetime, pre-exec interference and process-wide same-UID security remain outstanding. Tests use synthetic subprocesses, not real credentials or a real PAM policy. No runtime caller, installation or lock global is introduced.

## Experimental recovery client core (not installed)

The independent atelier-recovery-locker library accepts an explicitly supplied private Wayland socket; it does not discover or connect to the ambient desktop session. It binds the v1 lock protocol, requires a single output and one instance of each required global, creates a fresh surface without attaching or committing a buffer before configure, and acknowledges a valid configure before attaching an opaque black XRGB8888 shared-memory buffer. Buffer size is checked for overflow and capped at 64 MiB; backing storage is zero-filled and sealed against resizing (not content writes, since the Wayland server needs a shared writable mapping). Duplicate output, required global removal, repeated configure, rejection, or connection error ends the client rather than guessing a new route. It never sends unlock_and_destroy. The current library has no binary, authentication or password UI, installed files or runtime caller. It is not a usable screen locker. Unit tests cover sizing, size-sealed black storage, and topology rejection; client/server wire regression is in development; actual hardware presentation remains unverified. Native global registration remains disabled.
