# Adaptive panel layout

The panel retains its existing backend, focus actions, Quick Controls popover, application launcher, optional rice shortcut and live appearance visibility flags. Status (clock and battery) and system shortcuts are grouped in separate semantic containers. The wide mode presents icon plus label shortcuts; compact mode hides the shortcut text but preserves tooltips and accessible labels, shows time with the configured date in its tooltip, and reduces button padding. Workspace buttons remain numbered and preserve their confirmed-state indicators. The backend name remains in the launcher tooltip in compact mode.

The density rule uses logical monitor width, not the potentially oversized bar allocation: 1100px with four or fewer workspaces, plus 36px per additional workspace up to nine and 8px per configured spacing unit above eight. Unknown monitor geometry selects compact. These thresholds, paddings, and grouping are Atelier desktop adaptations inspired by Material adaptive layout principles, not published Material breakpoints. The existing panel tick re-evaluates geometry and density, updating presentation only when density changes. Buttons and popovers remain the same objects; no new surface or keyboard-focus policy.

An ordinary horizontally scrollable viewport constrains the bar even if unusually large fonts, many workspaces, or wide spacing exceed the available width. No enabled controls are deliberately removed to fit. Actual GTK allocation, scrollbar height and exclusive zone, touchpad scrolling, icon-theme fallbacks, popup anchoring within a scrolled viewport and multi-output behavior need desktop acceptance. The configured date is not silently changed in settings; compact mode only changes its presentation. No new dependencies or configuration schema. Unit tests cover logical width, workspace count, unknown geometry and spacing.
