# Native application launcher

The launcher is a normal GTK window shared by standalone and native shell sessions. Reopening presents the existing window in the same shell process. Search receives initial keyboard focus. Successful application activation closes the launcher; launch failures retain the view and report an error. Existing desktop utility shortcuts remain available.

The catalog uses GIO installed desktop entries, filters entries that should not be shown, deduplicates exact desktop IDs and preserves distinct entries without IDs. Search matches all whitespace-delimited terms across case-normalized name, ID, description, generic name, keywords and categories. Exact names and prefixes receive higher ranks; name terms rank above IDs and metadata. Ties retain catalog order. This is deterministic substring/word-prefix ranking with bounded single-edit name fallback, not semantic search or command execution. No usage history or remote lookup. Pinned uses existing dock pins, not a separate favorites database. Categories use recognized desktop-entry main category tokens, allow multiple memberships and fall back to Other. Search applies within the selected category.

The GTK list uses persistent rows with filter and sort functions, descriptions, application icons and pinned indicators. Search and category changes update the existing list, count and selection; nonempty searches select the best match. Enter in search launches the current best match, Down transfers focus to the list for native arrow navigation and activation, and Escape closes the window. Empty search Enter does not launch. Text and row labels use native accessible widgets. The catalog is refreshed when a new launcher window opens; no live installed-application monitor. 

References inspected: Caelestia's [AppList](https://github.com/caelestia-dots/shell/blob/main/modules/launcher/AppList.qml), [AppItem](https://github.com/caelestia-dots/shell/blob/main/modules/launcher/items/AppItem.qml), [Apps service](https://github.com/caelestia-dots/shell/blob/main/modules/launcher/services/Apps.qml) and [Content](https://github.com/caelestia-dots/shell/blob/main/modules/launcher/Content.qml). The implementation adapts descriptive result rows, prioritized search and keyboard activation without copying QML or adding its frequency database, special prefixes or command modes. Shared semantic colors style the selected row and its description. The 28px heading and 28px container radius derive from existing Material tokens; search padding, list spacing and desktop dimensions are Atelier choices. Existing user icon size and button radius remain in use. Neither the list nor the grid is virtualized and actual performance, keyboard activation and visual layout on desktop require acceptance testing.

Tests cover name-vs-metadata rank, case-insensitive multi-term search, empty and unmatched queries, exact multi-category membership and fallback. No new dependencies or configuration schema.

## Grid browsing and typo tolerance

The launcher defaults to its descriptive list, with an explicit Grid/List toggle. The responsive GTK FlowBox displays one to six columns as width permits, preserving the configured app icon size, exact dock-pinned markers, name, tooltip and accessible description. A shared rank vector drives both views, including category filtering, ordering, result count and empty state; the two widget collections remain in memory while the launcher is open. Enter in a nonempty search invokes the currently ranked first result through the common launch callback, and Down moves focus into the active view. Native GTK navigation handles subsequent directional keys. A new launcher window defaults back to the list; no preference is persisted. Grid tile minimum dimensions (96 logical pixels), spacing and layout are Atelier desktop design choices, not official Material component tokens. Semantic selection colors use the existing palette adapter.

Literal matches across name, ID and metadata always outrank typo-assisted matches. For an otherwise unmatched query term of four to 64 Unicode scalar values, the search permits one insertion, deletion, substitution or adjacent swap against a complete normalized name word. Every term must still match; fuzzy fallback does not run against arbitrary descriptions or command lines. Query length remains bounded. This is limited typo tolerance, not general fuzzy substring matching, transliteration, normalization of accents or arbitrary edit-distance ranking. Tests cover common errors, Unicode scalar comparison, all-term requirements, short-token rejection and literal priority. Actual GTK grid sizing, keyboard focus and large-catalog performance require desktop acceptance. No new dependencies, persistence or usage telemetry.
