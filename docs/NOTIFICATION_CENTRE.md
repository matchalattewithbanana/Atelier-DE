# Notification centre refinement

The inbox defaults to Active with application grouping enabled, and offers History and All views. Search, missed-only and exact application filters compose with the selected section. Active notifications are ordered by latest revision (ID breaks ties); groups follow the newest matching member. Closed history preserves the daemon's actual close order, including within groups. The header reports unfiltered active/history/missed counts. Cards use shared semantic container colors, configured notification radius, emphasized summaries, visible urgent/missed labels, closed reason and contained action buttons. Urgency is sender-reported, not a verified emergency. The inbox intentionally uses opaque card surfaces for readable history; popup opacity and popup styling remain unchanged. Layout sizes are Atelier choices, not claims of official Material notification components.

Dismissal now uses the additive DismissRevision(instance,id,revision) D-Bus method. Under the store mutex, only that active instance and revision can be dismissed. Old CLI Dismiss remains for compatibility. Inbox and toast no longer fall back to unreviewed ID dismissal; older daemons may report unsupported method until upgraded. Progress-only toast patches update the corresponding close callback's revision cell together with the displayed progress; action-bearing replacements rebuild. A displayed notification that has been replaced before a click cannot dismiss the replacement through this new method. Ownership of action-bearing notices remains bound to their originating sender after actions are consumed or removed through replacements; ordinary non-action CLI progress remains compatible.

Clear history is two-step, with a cancel option and explicit count of all closed entries, including filtered-out entries. The reviewed ordered ID/revision list and daemon instance are sent via ClearReviewedHistory. The store checks the full ordered list atomically before clearing; if history changed, no entries are cleared. A changed snapshot cancels local confirmation, and daemon-side validation protects against unseen changes. Active notifications are never cleared by this action. Existing CLI history methods are unchanged. No on-disk history, new daemon ownership, or changes to popup privacy policy. Inbox groups still rebuild when contents/filter change, and expansion is retained only for currently rendered groups of the same instance. Live bus and actual GTK acceptance remain necessary. Unit tests cover stale dismissal, stale history reviews, consumed action ownership, group ordering, section filtering and existing notification behavior.
