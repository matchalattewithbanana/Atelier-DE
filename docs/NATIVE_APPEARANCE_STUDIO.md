# Native Appearance Studio

The manager's Native Appearance Studio is a navigation hub for the independently deployed Settings product. Panel/dock/launcher, portable themes, wallpaper, desktop widgets, notifications, motion, window appearance and window rules use their existing native editors. Each opens through the verified run-product settings invocation; no Mango checkout is required and no second configuration store is introduced. The hub disables its launch buttons until the selected Settings process exits. Classic Appearance Studio remains separate.

The Shell appearance editor now includes a draft-only illustration of panel geometry, panel control visibility, launcher list/grid, icon sizes, button radius and dock pins/visibility. Three sample display profiles exercise the same automatic density decision as the live panel (1440/4, 800/4 and 1200/9 logical pixels/workspaces). The illustration uses the loaded shell palette if present, otherwise a clearly identified sample dark palette, with draft accent and saved panel/dock opacity. It uses abstract app glyphs and at most six pins plus fixed utilities. It is not an actual GTK shell screenshot, actual output allocation, wallpaper render, or timed live-session preview. Local dock-only reveal and fullscreen simulations show the dock, bottom reveal strip, or neither according to the draft enable/auto-hide/fullscreen preferences. The panel and launcher remain visible for comparison. Simulations are transient, do not query the compositor or trigger actual hover/timers, and assume a known native fullscreen state when selected. No file, global GTK style provider or live surface is modified by changing the draft or sample display.

The local native appearance profile adds optional panel-density (automatic, comfortable, compact) and launcher-grid-default (false by default) preferences. Existing version-one profiles load with previous behavior; default values are omitted from serialized profiles. Density applies through the existing appearance watcher; a new launcher window reads its opening view from the saved profile. The launcher toggle remains temporary. These behavioral preferences are intentionally not portable theme fields. The existing reviewed save, stale-byte guard and previous-version recovery are retained. Other native editors still save their own fields; reload before saving if another page changed the profile. This is one navigation hub, not an atomic multi-page draft transaction.

Tests cover density policy, backward-compatible default decoding, round-trip serialization, invalid preview colors and bounded Cairo rendering. Actual GTK presentation, verified deployment launch, cross-compositor panel overflow and migration of non-default profiles to older binaries still require acceptance. Older binaries with strict unknown-field validation may reject non-default newly saved preferences; update the native product set together, or restore a compatible previous profile before downgrading.

## Widget and notification draft previews

The existing native Widgets and Notifications editors now include sample-only Cairo illustrations using the same bounded scene renderer and loaded shell palette as the shell layout preview. The widget illustration follows the enabled group, left/right placement, requested width and fixed clock/calendar/media/system order. Saved button radius and widget background opacity are reflected. A clipped illustrative viewport and scrollbar marker indicate when the sample stack exceeds the native 440 logical pixel viewport. The marker is not an interactive scrollbar and sample card heights are not measured GTK requisitions. All displayed dates, media and resource values are fictional sample data, not a read of the user's session.

The notification illustration responds to draft style, position, preferred width, card radius, background opacity and maximum stack size. The presenter and preview share the existing style/position resolution and a common card-limit rule: floating always shows one card; island/compact permit one to three. A local launch-mode simulation resolves Follow shell launch mode, and a local unavailable-session simulation demonstrates the advisory hide preference. Neither changes real launch flags, logind state, daemon state or popup visibility. The preview does not send notifications, connect to providers, animate transitions, wait for timeouts or simulate monitor selection. Geometry is illustrative and the palette uses the loaded native profile or sample dark colors, not a live wallpaper. All simulations are transient. Each editor retains its reviewed save, defaults, reload and previous-version recovery; no new persistence fields or dependencies. Tests cover card order/visibility, style and position resolution, floating limit and Cairo rendering of representative extreme configurations. Real desktop visual acceptance remains necessary.
