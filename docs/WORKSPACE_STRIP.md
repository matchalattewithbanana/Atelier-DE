# Expressive workspace strip

The existing product-neutral workspace backend remains the sole source of workspace state and the only route for focus requests. Four native workspaces and up to nine external numbered tags retain their existing behavior. No speculative workspace selection, new command syntax, task occupancy inference or output-specific workspace mapping. The strip supports every active index in the backend snapshot, including multiple simultaneously active indices from external monitor inventories.

Native GTK buttons remain directly interactive and accessible, with confirmed active styling and a separate noninteractive drawing area below the buttons. Homogeneous numeric cells and fixed indicator height prevent animation from changing button allocations. Each indicator independently retargets an expressive fast spatial SpringValue; changes in confirmed state animate the width within that cell. It is a per-cell transition, not a single moving pill or a compositor workspace-switch animation. The outgoing mark may shrink while the newly confirmed button is already selected. The immediate selected-button color and accessible label represent confirmed state. Unavailable snapshots clear marks immediately, disable the buttons, and identify the unavailable state; initial discovery/reconnection snaps to the new confirmed state. Reduced-motion settings and GTK animation disable snap springs, and frame-clock callbacks stop when all springs settle.

The reference is Caelestia's [ActiveIndicator.qml](https://github.com/caelestia-dots/shell/blob/main/modules/bar/components/workspaces/ActiveIndicator.qml), which moves two independently animated edges around the active workspace. Atelier adapts its active-indicator emphasis with independent per-cell marks to support more than one active index. The fast spatial spring uses shared Material-derived tokens. The 26px maximum width, 7px reserved indicator area, 4px stroke and numeric left-to-right layout are Atelier desktop choices, not official Material workspace tokens. Existing panel spacing and button radius remain configurable; the workspace group uses the semantic container and selected color pair.

Tests cover multiple active indices, failed reads, reconnection, reduced motion and rapid retargeting within cell bounds. The existing panel's one-second snapshot refresh and external helper polling remain; this patch does not introduce event subscriptions, occupancy, live multi-output placement, keyboard focus policy changes or compositor-side workspace transitions. Actual GTK geometry, accessibility and cross-compositor visual acceptance remain necessary.
