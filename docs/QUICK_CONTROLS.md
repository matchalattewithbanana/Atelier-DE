# Native shell quick controls

The quick controls window is available from the standalone launcher and the native panel's existing audio entry (which still respects the show_audio preference). The layer panel uses a native GTK popover on layer-shell protocol version 4 or newer; older compositors and the standalone launcher use the ordinary GTK window. Neither is a lock-screen surface. Reopening focuses the existing window.

## Reference and visual direction

Inspected Caelestia's [AudioPopout.qml](https://github.com/caelestia-dots/shell/blob/main/modules/bar/popouts/AudioPopout.qml), [FilledSlider.qml](https://github.com/caelestia-dots/shell/blob/main/components/controls/FilledSlider.qml), [StyledSlider.qml](https://github.com/caelestia-dots/shell/blob/main/components/controls/StyledSlider.qml), [dashboard Media.qml](https://github.com/caelestia-dots/shell/blob/main/modules/dashboard/dash/Media.qml) and [Details.qml](https://github.com/caelestia-dots/shell/blob/main/modules/dashboard/media/Details.qml). The references separate device and volume controls, use distinct active/inactive track colors and narrow slider handles, and prioritize play/pause inside a grouped media transport row. Atelier implements original GTK controls, not copied QML.

From Material 3: 28-unit extra-large radius, emphasized headline medium (28/36, weight 500), title large (22/28, weight 500), title medium emphasized (16/24, weight 700), 48-unit minimum target for setting controls, 16-unit slider track and narrow 4-unit handle. Atelier adaptations: GTK logical pixels, card padding and spacing, 24px rounded buttons with a 12px pressed radius, 40px slider handle height, and explicit volume Apply buttons. GTK CSS applies only within the new quick controls/media windows, using the shared palette role adapter or GTK's native theme fallback. These are native approximations, not pixel-identical Material components. Custom saved palettes and existing geometry preferences are not overwritten. The media wave and confirmed toggle transitions are described below.

## Behavior

Wi-Fi and Bluetooth show provider-confirmed states; an explicit button sends the inverse of the displayed state. Audio shows the reported default input and output device, known channel average, mute state, and an editable 0–100% volume draft. Values above 100% are reported as-is; explicitly applying 100% can reduce an amplified volume. Unknown channel volume disables the slider; missing default IDs never trigger a guessed device. Apply/mute target the displayed named device, with the service's existing validation. Inline selectors list input/output devices, explicitly identify monitors and the current default, and permit setting a selected device as default. Selection alone changes nothing; volume and mute still act on the displayed confirmed default, not a pending selection. Refresh replaces selections and drafts. Detailed management remains available in Settings.

Each card owns a separate worker, bounded one-request channel and snapshot reply channel. GTK never invokes blocking service calls. The card disables while a request is pending and receives a new provider snapshot after success or failure. Cards refresh when mapped or explicitly refreshed, replacing volume drafts. No periodic provider polling; the GTK reply timer runs only while a request is outstanding. This avoids overwriting user edits and repeated provider processes. Provider absence or failure is reported per card, with controls disabled where state is unknown. Radio changes may affect connectivity system-wide; the window does not request sudo. Existing optional pactl, nmcli and bluetoothctl provider requirements and authorization behavior remain unchanged. These controls are only for unlocked desktop use.

Media now uses direct session-bus MPRIS calls on a dedicated worker. The existing playerctl service remains available to CLI and desktop widget consumers. The interactive window discovers bus names and reads typed properties for only the selected player, showing real title, artist, album, position, duration and capability-aware controls. Selected-player signals trigger authoritative reads; playback position is additionally sampled every two seconds while playing. The accessible GTK scale permits a seek draft followed by explicit Seek; refresh preserves it only for the same player owner, track ID and length. Generation-tagged replies cannot overwrite newer selections or requests. Before every action the worker resolves the well-known name to the original unique owner and rechecks current capabilities. SetPosition sends a typed track object path and absolute microsecond position to that unique owner; compliant players ignore seeks for stale tracks. Missing or malformed metadata disables seeking. Local artwork and a separate expressive wave indicator are described below. Automatic seek-on-release, broader provider subscriptions, spring-driven toggle morphing and real visual/provider acceptance remain outstanding.

Tests cover the average of known channel percentages, unknown defaults, and scoped CSS. Native GTK visual and hardware/provider acceptance are still required.

Additional tests cover typed MPRIS properties, unknown capabilities, exact SetPosition signature, stale track and invalid seek bounds, and duration formatting. Native bus calls use a 1.5-second per-call timeout and no auto-start. Session bus connection setup is delegated to GIO. Real player and device acceptance remains pending.

## Cover artwork and expressive progress

The media window offers an unchecked, per-window opt-in to read player-provided local cover art. Only file:/// URIs with no hostname, query, fragment or parent-directory component are accepted. Remote HTTP(S), data and other URI types are not fetched. The existing bounded image decoder rejects final symlinks/nonregular files, limits inputs to 32 MiB and 24 million pixels, and normalizes PNG/JPEG/WebP to at most 512 pixels per edge. This is an unprivileged local file read, not a sandbox: directory symlinks and mounted filesystems are not excluded. Only enable it for trusted players. One in-memory result (including failures) is cached by player owner, track, title, album and URI, discarded on consent withdrawal or player change; same-key file changes are not watched. No persistent cover cache, remote image downloads or changes to saved theme settings. The GTK picture receives decoded pixels, not a URI. Failed or unsupported artwork is hidden.

Artwork sampling uses the existing bounded histogram and HCT tonal-spot generator to derive both light and dark readable palettes. The derived background and accent color apply only to the wavy playback indicator; the rest of the media window keeps its desktop theme. A missing/invalid artwork palette falls back to GTK foreground colors. The indicator follows the selected player's real position or current seek draft; it animates a decorative wave phase while playing, pauses during seek drafts and respects GTK's animation setting. The GTK scale remains available under Keyboard seek controls, and the explicit track-bound Seek button commits either kind of draft. The wave is now a pointer/touch seek surface; it is not an audio visualizer. Geometry and timing are Atelier adaptations of Caelestia's StyledSlider and media Details patterns. No live position extrapolation or persistent artwork permission. Tests check local URI restrictions, palette contrast and Cairo drawing at empty/full/invalid/tiny sizes. CI and real player visual testing remain necessary.

## Interactive wave and playback modes

The wave accepts click/drag input through GTK GestureDrag, mapping the horizontal pointer coordinate to the same bounded endpoints used by the renderer. It edits the shared seek draft and never calls MPRIS while dragging. The explicit Seek button applies the selected position. Gestures retain the original Track identity (unique player owner, track ID, duration); a changed track or pending action invalidates the gesture. The native scale remains available under a keyboard-seek expander. The wave has a 48 logical-pixel target, a narrow 4px marker and intentionally fixed left-to-right time direction. The target size and handle width are Material-derived; the wave geometry and confirmation behavior are Atelier adaptations. Gesture cancellation ends the gesture without sending a seek; the draft may remain for review. Native input and assistive technology acceptance still need testing.

Shuffle and repeat read optional typed MPRIS Shuffle and LoopStatus properties, requiring CanControl. Repeat cycles None → Track → Playlist → None. Requests carry the expected displayed value, recheck the unique bus owner and fresh properties, then write the typed value through Properties.Set to the exact owner. Unknown/malformed properties disable their controls; a player may expose a readable but non-writable property, in which case the service reports the write error and refreshes. This is not an atomic compare-and-swap against external controllers. Buttons show the confirmed post-action state, not an optimistic toggle. Tests cover coordinate bounds, typed property writes, stale values, and unknown capabilities. CI and actual MPRIS/GTK acceptance remain necessary.

## Reactive media worker

The interactive player owns a private GLib main context on its worker thread. It subscribes to MPRIS namespace NameOwnerChanged, selected unique owner Player PropertiesChanged and Seeked signals. Signals mark a dirty bit only; metadata, capabilities, position and actions continue to use authoritative reads and exact owner checks. Other player owners cannot invalidate selected-player properties. A minimum 100 ms refresh spacing after a delivered snapshot coalesces bursts. User requests wake the context immediately via a bounded channel; the worker sleeps in context iteration between events rather than a fixed short polling loop. A two-second fallback samples position during playback and retries failures; paused, stopped, and empty player lists reconcile every 15 seconds for compatibility with incomplete MPRIS implementations. Playback position is not extrapolated. Subscription IDs are removed when a connection is discarded, and channel closure wakes the worker. The existing GTK reply receiver still checks its bounded queue every 100 ms while the media window is open; this change does not eliminate all UI polling. Cover decoding and bus calls remain serialized on the worker. The window is not a global media daemon; audio, network and Bluetooth subscriptions remain future work.

Tests exercise invalidation filtering and coalescing, private context deadlines and request/disconnect handling. Real session-bus signals, player replacement, external transport actions, reconnection and desktop acceptance still need integration testing. No new dependencies or saved configuration changes.

## Panel-anchored quick controls

References inspected: Caelestia's [popout Wrapper](https://github.com/caelestia-dots/shell/blob/main/modules/bar/popouts/Wrapper.qml), [popout Content](https://github.com/caelestia-dots/shell/blob/main/modules/bar/popouts/Content.qml) and [IconButton](https://github.com/caelestia-dots/shell/blob/main/components/controls/IconButton.qml). Atelier adopts anchored, on-demand presentation and distinct confirmed active shapes, without importing QML or Hyprland-specific focus grabs.

The existing panel audio entry now opens a lazily constructed GTK MenuButton/Popover on layer-shell protocol version 4 or newer. GTK handles positioning, pointer dismissal and Escape; the parent panel requests on-demand keyboard mode while mapped and restores None on unmap. It never requests exclusive keyboard focus. Older layer-shell versions retain the standalone window fallback. The popover has a scrollable height cap derived from its panel monitor when available (Atelier desktop sizing, not an official M3 token). No absolute output coordinates, new layer window or additional exclusive zone. Actual nested-popup and keyboard behavior must be checked on Atelier, MangoWM, Hyprland and Niri; the protocol check does not guarantee every compositor implementation behaves identically.

The shared view has Connectivity and Audio tabs, collapsible microphone/input controls, and shortcuts to detailed settings and the media window that dismiss the popup first. Card refresh occurs on map; a single outstanding request per card remains serialized even if the popup closes and reopens. Hidden idle cards retain dormant workers but run no continuous reply timers or provider calls. Already-started actions can complete after dismissal. Standalone and panel views share implementation, not a process-global service worker. Explicit refresh remains available. Network or Bluetooth changes can affect connectivity and may require the system's existing authorization.

Confirmed radio/mute states use scoped GTK CSS corner transitions from 24 to 12 logical pixels. This is an Atelier radius adaptation and a timed CSS easing, not a spring-driven shape path morph. The transition uses the existing local motion duration and zero duration for reduced motion; stack page crossfades read that preference when constructed. No global GTK styling change. Fresh CI and real compositor/keyboard/visual acceptance remain necessary.
