# Native shell quick controls

The quick controls window is available from the standalone launcher and the native panel's existing audio entry (which still respects the show_audio preference). It is a normal GTK window, not a layer-shell popover or lock-screen surface. Reopening focuses the existing window.

## Reference and visual direction

Inspected Caelestia's [AudioPopout.qml](https://github.com/caelestia-dots/shell/blob/main/modules/bar/popouts/AudioPopout.qml), [FilledSlider.qml](https://github.com/caelestia-dots/shell/blob/main/components/controls/FilledSlider.qml), [StyledSlider.qml](https://github.com/caelestia-dots/shell/blob/main/components/controls/StyledSlider.qml), [dashboard Media.qml](https://github.com/caelestia-dots/shell/blob/main/modules/dashboard/dash/Media.qml) and [Details.qml](https://github.com/caelestia-dots/shell/blob/main/modules/dashboard/media/Details.qml). The references separate device and volume controls, use distinct active/inactive track colors and narrow slider handles, and prioritize play/pause inside a grouped media transport row. Atelier implements original GTK controls, not copied QML.

From Material 3: 28-unit extra-large radius, emphasized headline medium (28/36, weight 500), title large (22/28, weight 500), title medium emphasized (16/24, weight 700), 48-unit minimum target for setting controls, 16-unit slider track and narrow 4-unit handle. Atelier adaptations: GTK logical pixels, card padding and spacing, 24px rounded buttons with a 12px pressed radius, 40px slider handle height, and explicit volume Apply buttons. GTK CSS applies only within the new quick controls/media windows, using the shared palette role adapter or GTK's native theme fallback. These are native approximations, not pixel-identical Material components. Custom saved palettes and existing geometry preferences are not overwritten. No animation or wavy seekbar is claimed by this patch.

## Behavior

Wi-Fi and Bluetooth show provider-confirmed states; an explicit button sends the inverse of the displayed state. Audio shows the reported default input and output device, known channel average, mute state, and an editable 0–100% volume draft. Values above 100% are reported as-is; explicitly applying 100% can reduce an amplified volume. Unknown channel volume disables the slider; missing default IDs never trigger a guessed device. Apply/mute target the displayed named device, with the service's existing validation. Full device selection and detailed management remain in the existing Settings pages, accessible via Open settings.

Each card owns a separate worker, bounded one-request channel and snapshot reply channel. GTK never invokes blocking service calls. The card disables while a request is pending and receives a new provider snapshot after success or failure. No automatic periodic polling; Refresh explicitly checks external changes and replaces a volume draft. This avoids overwriting user edits and repeated provider processes. Provider absence or failure is reported per card, with controls disabled where state is unknown. Radio changes may affect connectivity system-wide; the window does not request sudo. Existing optional pactl, nmcli and bluetoothctl provider requirements and authorization behavior remain unchanged. These controls are only for unlocked desktop use.

Media keeps the existing MPRIS worker and player selection, with a contained card, state-aware central Play/Pause button, and tonal Previous/Next controls. No cover art, duration, seeking, shuffle/repeat, capability enumeration or animated waveform is added yet; the current playerctl snapshot lacks those fields. Future work should extend the MPRIS service boundary and use actual capability-aware controls before adding a wavy seekbar or artwork. Next: inline device selectors, true popover/adaptive layout, interruptible toggle morphs, slider drag/commit behavior with stale state checks, live provider subscriptions, and real visual testing.

Tests cover the average of known channel percentages, unknown defaults, and scoped CSS. Native GTK visual and hardware/provider acceptance are still required.
